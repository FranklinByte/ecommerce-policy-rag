# 局限、实验解释与不能宣称的内容

## 冻结结果速读

结构化分块共 43 个 chunk，滑动窗口共 16 个。结构化 BM25、Hybrid、Hybrid+Rerank 的文档 Recall@5 均为 1.0000，Dense 为 0.9917。这个规模下 BM25 已很强，不能声称 Hybrid 带来显著 Recall 提升。

结构化 Hybrid+Rerank 的 MRR@5=0.9750，和 Hybrid 相同；p95 则从约 70.5 ms 增至 3844.2 ms。滑动窗口 Hybrid 的 MRR@5=0.9917，高于同策略 Rerank 的 0.9833，重排并非每个设置都改善排序。

| 结构化模式 | 引用 Precision（有引用时） | 引用 Recall（所有可答） | 可回答接受率 | 无答案拒答率 |
|---|---:|---:|---:|---:|
| BM25 | 0.9412 | 0.5500 | 0.5667 | 0.9167 |
| Dense | 0.9233 | 0.8250 | 0.8333 | 1.0000 |
| Hybrid | 0.9397 | 0.7833 | 0.7833 | 1.0000 |
| Hybrid+Rerank | 0.9470 | 0.7083 | 0.7333 | 1.0000 |

这意味着结构化重排模式在 12 条无答案样例中全部拒答，但 60 条可答样例仅回答了 44 条。不能将 100% 拒答率或 94.70% 条件引用 Precision 描述为“整体回答准确率”。这些均是抽取式结果，不是 LLM 事实正确率。

## 实验口径与产物

最终运行目录为 [`eval-results/frozen-2026-09-06`](../eval-results/frozen-2026-09-06/report.md)。每个实验有独立 `retrieval.json/csv`、`generation.json/csv`、`failures.json`，摘要包含源码/配置/数据集/依赖锁哈希、模型 commit、索引时间、RSS 和全部分数。`failure-analysis.md` 按类别统计失败并列举案例。

`baseline-2026-09-06` 是早期实现的真实运行快照，不是冻结版本：当时尚未逐候选过滤弱证据、完善政策系列冲突门控和滑动窗口章节映射。保留它是为了审计演变，不把它与冻结结果挑优混用，也不声称差异经过统计显著性验证。没有按实验结果修改固定标签或降低运行阈值。

两种分块得到不同数量的 chunk，而评测相关性只有文档级。先将 Top-5 chunk 去重成文档序列，再计算 Recall@1/3/5、MRR@5、nDCG@5；因此一个错误条款只要属于正确文档也可能被算作命中。高 Recall 不能代替 chunk/条款级人审。跨文档样例的 Recall@1 上限本来就可能小于 1。

引用 Precision 的分母仅为实际有引用的可回答样例；拒答的 Precision 未定义，不能填 1。所有可回答样例都进入引用 Recall 分母，拒答记 0；另报引用覆盖率、可回答接受率和无答案拒答准确率，防止“全部拒答”造成误导。没有用字符串包含 expected_facts 代替事实正确性审核，也没有 LLM-as-Judge 分数。

## 已知失败类型

| 类型 | 原因与可审计证据 | 不应做的解释 |
|---|---|---|
| 可回答问题被拒绝 | 独立工程阈值偏保守；短问句 BM25 分数受过滤后 IDF 影响；看 generation.refusal_reason | 不能只展示无答案拒答率而不报接受率 |
| 相关文档命中但条款未齐 | RRF/重排仅处理已召回窗口；抽取器最多用三个达阈值片段 | 文档 Recall=1 不代表回答完整 |
| 多版本语义十分相似 | 同系列两个版本都超过门槛时拒答；无日期与版本时不能擅自选新版本 | 新 PDF 上传时间不是所有旧合同的失效日期 |
| 宽泛跨文档问题 | 可能召回标准保修与两个 AppleCare+ 版本，门控优先要求澄清 | 不能将保守拒答伪装成检索漏召回 |
| 无答案硬负例出现高关键词分 | BM25 只衡量词项统计，密集政策词可能有高分 | BM25 分数不是“可退货概率” |
| Rerank CPU 延迟 | CrossEncoder 对多个 query-document 对联合编码；不像独立向量点积 | 不能宣称开启 Rerank 无成本或总优于 BM25 |

运行环境是共享开发机。实验逐条顺序执行，模型加载 warmup 单独记录；它不是独占硬件、多轮显著性研究或并发压测。不同模式/分块按固定顺序运行并共享已加载模型，缓存、温度、其他本地检查会影响延迟。需要严谨性能结论时应在独占环境中多轮随机顺序运行。

索引时间第一次含 Embedding 冷加载，第二种策略复用模型；不能将二者耗时差全部归因于分块。Windows `peak_wset` 是进程生命周期高水位，Linux 回退为当前 RSS；既不是索引独占内存，也不是 Qdrant Server 总内存。`index_size_bytes` 是本地文件大小，服务端 collection 的磁盘占用未包括在内。

## 业务与模型边界

- 数据规模小：7 份真实来源摘要、4 份虚构政策，适合回归与面试演示，不代表跨平台真实全量售后知识。72 条查询均为 AI 辅助编写，未经过独立人审；没有线上日志或真实客服胜率。
- 真实页面适用时间未知，指定历史日期会排除未知文档。真实 PDF 的版本区分被实现；确定生效/失效时间边界的正确性主要通过合成 fixture 验证。
- 默认答案是抽取式证据说明，不会判断消费者是否一定有退款权，不计算三包法律期限，不验证故障真伪。拆封/激活/购买时间可输入，但不会触发外部业务接口或自动裁决。
- 缺失信息提示基于结构化字段，未做通用自然语言槽位提取；问题里提到型号但没有填型号字段时，可能仍提示补充。适用/不适用列表为保守关键词抽取，不是条件逻辑求解器。
- 可选提供商只验证 JSON、引用 ID 范围和标记对应；不能证明每句话都被引用蕴含，也不能代替人工事实审核。**本次没有执行真实付费 LLM 生成评测**。
- HTML 支持可直接获取的文本，不执行 JavaScript；PDF 支持文字层/页号，不支持 OCR、扫描件或可靠的复杂跨页表格重建。原文导入实验与摘要实验必须分开建库、分开评测。
- 分块按字符计数，模型按 token 截断，长片段仍可能被 512-token CrossEncoder 截断。生产扩展应按 tokenizer 预算对齐并标注长条款测试。
- Qdrant Local 和本项目 BM25 适用于小语料。虽然 Compose 真正使用 Qdrant Server，但没有证明百万级 HNSW 性能。没有做 GPU 压测、分布式索引、权限隔离、多租户、生产认证或 SLA。
- 本地接口无账号系统，只绑定 loopback；不要直接公开到公网。索引版本保留但不自动清理；目录操作由本地 CLI 操作者负责。

## 简历可以怎样表述

可以说：实现了版本感知的中文 BM25/Dense/RRF/Rerank 四路对照与证据问答，固定 BGE 模型、Qdrant 索引、源码/文档哈希与 72 条 AI 辅助回归集，完成本地 API/UI、测试和 Docker 验证。具体指标必须连同语料规模、文档级口径和接受率一起说明。

不能说：自研 Embedding 模型、独立人工标注百条真实客服问题、线上准确率接近 100%、具备法律裁决能力、生产高并发、云端 CI 已通过、已经验证真实 LLM 幻觉率，或把成熟开源产品改名作为原创。
